# パイロットサークル受け入れガイド (運営者用)

知人サークルを complimentary プラン (全機能無料) で受け入れる際の手順。
2026-09-13 時点 (v4.0.x、P4 実装後) の運用。

## 全体の流れ

1. 【先方 or 運営】サークル情報を申請する
   - 先方に `/apply` から申請してもらう、または運営が `/platform` の「新規テナント作成」で直接作る
2. 【運営】`/platform` で申請を承認 (slug 確定) → テナント作成される
3. 【先方】LINE Developers でチャネルを作る (下記「サークル側にやってもらうこと」)
4. 【運営】`/platform` → 対象テナントの「LINE設定」でチャネル情報を登録
5. 【先方】サークルの URL (`https://<アプリのドメイン>/<slug>`) にアクセスして LINE ログイン
   - 最初にログインした先方の代表者を、運営が `/28bad` 側の…ではなく **そのテナントの URL の管理画面** で admin に昇格させる
     (メンバー管理はテナント URL 配下で行う。最初の 1 人は運営が platform 管理者権限で承認する)
6. 【先方】メンバーに URL を展開して利用開始

## サークル側にやってもらうこと (案内テンプレ)

> アプリを使うには、サークル専用の LINE 連携設定が必要です (無料)。
> 以下の 2 つを LINE Developers (https://developers.line.biz/) で作成してください。
>
> **1. LINE Login チャネル** (メンバーがログインに使う)
> - プロバイダーを新規作成 (サークル名で OK)
> - 「LINE ログイン」チャネルを作成
> - コールバック URL に次を登録:
>   `https://<アプリのドメイン>/api/auth/callback/line`
> - 「チャネル ID」と「チャネルシークレット」を運営に共有してください
>
> **2. Messaging API チャネル** (アプリからの LINE 通知に使う。任意、後からでも可)
> - 同じプロバイダー内に「Messaging API」チャネルを作成
> - 「チャネルアクセストークン (長期)」を発行
> - 「チャネル ID」「チャネルシークレット」「アクセストークン」を運営に共有してください
> - ※ 無料プランは月 200 通まで。サークルの規模によっては通知の使い方に注意
>
> 共有いただいた情報は運営がアプリに登録します。登録後、
> `https://<アプリのドメイン>/<サークルID>` からメンバーがログインできるようになります。

## 運営側の注意点

- **秘密情報の受け渡し**: チャネルシークレット/トークンはチャットに平文で流させない
  (使い捨ての共有手段を案内する)。登録後は手元に残さない
- **テナントのプラン**: パイロットは `complimentary` にする (`/platform` で切替)。
  Stripe 統合 (P2.5) までは paid プランにしても課金は発生しないので使わない
- **通知が送れない場合**: Messaging API 設定が未登録のテナントでは LINE 通知は
  静かにスキップされる (メール通知は使える)

## 既知の制約 (パイロット時点)

- **リマインダー cron は 28ばど のイベントのみ対象** (他テナントのリマインダー通知は未対応。
  P5 で cron のテナント横断イテレーションを実装予定)
- **LINE のユーザー ID はプロバイダー単位**のため、同じ人が複数サークルに参加する場合、
  サークルごとに別アカウントになる (大会実績のサークル横断共有は同一プロバイダー内でのみ機能)
- SystemSetting (公式 LINE URL 等) はまだグローバル 1 セットのため、テナント別設定は未対応
